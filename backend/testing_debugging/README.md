# Member 3: Testing, Debugging & Docker Subsystem
**AI-DevTeam / AutoDev Platform**

---

## 1. Executive Summary & Mission

Member 3 owns the end-to-end automated testing, verification, diagnosis, self-correction, and telemetry reporting lifecycle for software generated by the AI DevTeam.

The mission of this subsystem is to guarantee that no software generated by upstream agents (Members 1 and 2) reaches downstream security review (Member 4) or production deployment without passing verified test suites executed within isolated, resource-bounded Docker containers. If tests fail, the subsystem diagnoses the root cause, applies surgical, syntax-checked code patches, and orchestrates a bounded repair loop.

## 6. Docker Sandbox Setup & Pre-built Image

The Docker Sandbox requires Docker Desktop (or Docker Engine on Linux) to be running.

### 6.1 Building the Hardened Pytest Sandbox Image
Because Member 3 containers run with `network_mode="none"` for zero-trust network isolation, Pytest must be pre-installed inside the base image:

```powershell
# Build the local sandbox image with pytest pre-installed:
docker build -t python:3.11-slim -t autodev-sandbox:python3.11 - <<EOF
FROM python:3.11-slim
RUN pip install --no-cache-dir pytest
WORKDIR /workspace
EOF
```

### 6.2 Container Security Constraints Enforced by `DockerSandbox`:
- **Network Isolation:** `network_mode="none"` (no outbound internet or LAN access).
- **Non-Privileged:** `privileged=False` and dropped Linux capabilities.
- **Resource Quotas:** Memory capped at `256m`, CPU quota `100000` (1.0 core), max processes `64` (fork-bomb prevention).
- **Prohibited Mounts:** Rejects attempts to mount `/var/run/docker.sock`, Windows named pipe `//./pipe/docker_engine`, system root directories, or non-workspace paths.
- **Read-Only Root Filesystem:** Root filesystem mounted read-only where supported; write access confined to `/workspace` and `/tmp`.
- **Automatic Lifecycle:** Ephemeral containers killed and removed forcefully upon completion or timeout.

## 8. LangGraph Integration for Member 1

Member 1 can connect Member 3 directly into the central `StateGraph(AgentState)`.

### 8.1 Node Signatures
All nodes take and return `AgentState` (`TypedDict` from `backend/schemas/state.py`):

```python
from backend.testing_debugging import (
    testing_node,             # (state: AgentState) -> AgentState
    bug_detection_node,       # (state: AgentState, single_step: bool = True) -> AgentState
    report_generation_node,   # (state: AgentState) -> AgentState
    route_after_testing,      # (state: AgentState) -> str
    route_after_debugging,    # (state: AgentState) -> str
)
```

### 8.2 Routing Identifiers
- **After Testing (`route_after_testing`):**
  - `"code_review"`: All tests passed cleanly -> route to Member 4.
  - `"bug_detection"`: Tests failed and `retry_count < MAX_RETRY_LIMIT` -> route to Bug Detection.
  - `"generate_report"`: Retries exhausted or unrecoverable Docker infrastructure error -> route to Report Generator.
- **After Debugging (`route_after_debugging`):**
  - `"code_review"`: Post-repair tests passed -> route to Member 4.
  - `"bug_detection"`: Tests still fail and `retry_count < MAX_RETRY_LIMIT` -> loop for next repair attempt.
  - `"generate_report"`: Retries exhausted, diagnosis inconclusive, or patch rejected -> route to Report Generator.

### 8.3 Central Graph Connection Example
```python
from langgraph.graph import StateGraph, END
from backend.schemas.state import AgentState
from backend.testing_debugging import (
    testing_node,
    bug_detection_node,
    report_generation_node,
    route_after_testing,
    route_after_debugging,
    ROUTE_CODE_REVIEW,
    ROUTE_BUG_DETECTION,
    ROUTE_GENERATE_REPORT,
    NODE_TESTING,
    NODE_BUG_DETECTION,
    NODE_REPORT_GENERATION,
)

workflow = StateGraph(AgentState)

# Register Member 3 nodes
workflow.add_node(NODE_TESTING, testing_node)
workflow.add_node(NODE_BUG_DETECTION, bug_detection_node)
workflow.add_node(NODE_REPORT_GENERATION, report_generation_node)

# Conditional routing from testing
workflow.add_conditional_edges(
    NODE_TESTING,
    route_after_testing,
    {
        ROUTE_CODE_REVIEW: "code_review",              # Hand off to Member 4
        ROUTE_BUG_DETECTION: NODE_BUG_DETECTION,        # Failed tests -> Bug Agent
        ROUTE_GENERATE_REPORT: NODE_REPORT_GENERATION,  # Exhausted/infra failure -> Report
    },
)

# Conditional routing from bug detection
workflow.add_conditional_edges(
    NODE_BUG_DETECTION,
    route_after_debugging,
    {
        ROUTE_CODE_REVIEW: "code_review",              # Fixed -> Hand off to Member 4
        ROUTE_BUG_DETECTION: NODE_BUG_DETECTION,        # Bounded retry loop
        ROUTE_GENERATE_REPORT: NODE_REPORT_GENERATION,  # Exhausted/inconclusive -> Report
    },
)

workflow.add_edge(NODE_REPORT_GENERATION, END)
```

## 9. Member 4 Handoff Contract

When tests pass, the workflow routes to `"code_review"` with the following guarantees:
- `is_test_passed`: `True`
- `status`: `"reviewing"`
- `test_results`: Complete metrics (`passed=True`, `total_tests > 0`, `failed_tests=0`).
- `patched_files`: Populated with all modifications applied during self-correction (`[{"path": rel_path, "content": code}]`), allowing Member 4 to review patched code.
- `workspace_path`: Intact, verified on-disk directory ready for security and OWASP analysis.
