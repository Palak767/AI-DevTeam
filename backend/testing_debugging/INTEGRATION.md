# Member 3: Testing, Debugging & Docker Subsystem – LangGraph Integration Guide

**Module:** `backend.testing_debugging`  
**Owner:** Member 3 (Testing, Debugging & Docker)  
**Target Consumer:** Member 1 (Pipeline Orchestration & StateGraph Architect)  
**Downstream Consumer:** Member 4 (Code Review & Security Analysis Agent)

---

## 1. Overview

The Member 3 subsystem encapsulates automated test synthesis, containerized Pytest execution, root-cause diagnosis, atomic self-correction, and audit report generation into a robust LangGraph-compatible sub-workflow.

Member 1 can integrate Member 3 in two ways:
1. **Direct Node Integration (Recommended):** Register `testing_node`, `bug_detection_node`, and `report_generation_node` directly into the central `StateGraph(AgentState)` with conditional routers `route_after_testing` and `route_after_debugging`.
2. **Compiled Subgraph Integration:** Mount the standalone compiled sub-workflow generated by `build_testing_subgraph()` as a composite node in the central graph.

## 3. Node Signatures and Behavioral Contracts

All Member 3 nodes accept and return the standard shared `AgentState` (`TypedDict` defined in `backend/schemas/state.py`). Every node guarantees:
- Non-destructive updates (unrelated state fields are preserved).
- Internal error containment (unhandled runtime exceptions do not crash the workflow).
- Real-time logging appended to `state["logs"]`.
- Stepper synchronization (`current_agent` and `status` fields updated).

### Node 1: `testing_node`
```python
def testing_node(state: AgentState) -> AgentState
```
- **Role:** Generates comprehensive Pytest test cases using Gemini, saves them safely in the workspace, and runs Pytest in an isolated, read-only Docker container via `TestExecutor` and `DockerSandbox`.
- **Inputs Consumed:** `workspace_path`, `generated_files`, `requirement_spec`.
- **State Fields Updated:**
  - `current_agent`: `"Testing Agent"`
  - `status`: `"testing"` (or `"reviewing"` if passed, `"debugging"` / `"failed"` if failed)
  - `test_results`: Serialized `TestResult` (`passed`, `total_tests`, `passed_tests`, `failed_tests`, `raw_output`, `error_summary`)
  - `is_test_passed`: `bool`
  - `logs`: Appended with test generation and Docker execution telemetry.

### Node 2: `bug_detection_node`
```python
def bug_detection_node(state: AgentState, single_step: bool = True) -> AgentState
```
- **Role:** Analyzes Pytest failures and stack traces, proposes safe surgical code patches, applies them atomically with syntax and security validation, and reruns tests.
- **Inputs Consumed:** `workspace_path`, `generated_files`, `test_results`, `retry_count`, `requirement_spec`.
- **State Fields Updated:**
  - `current_agent`: `"Bug Detection Agent"`
  - `status`: `"debugging"` (or `"reviewing"` if patch succeeded, `"failed"` if retries exhausted or inconclusive)
  - `retry_count`: Incremented by 1 per repair attempt (up to `config.MAX_RETRY_LIMIT`).
  - `is_test_passed`: Updated to `True` if rerun passes.
  - `bug_diagnosis`: Root cause explanation string (e.g. `"[syntax_error] Unterminated string literal"`).
  - `patched_files`: List of modified files `[{"path": rel_path, "content": patched_code}]`.
  - `test_results`: Updated with post-repair rerun metrics.
  - `logs`: Appended with diagnosis and patch audit events.

### Node 3: `report_generation_node`
```python
def report_generation_node(state: AgentState) -> AgentState
```
- **Role:** Synthesizes structured JSON and human-readable Markdown test reports, redacting all sensitive credentials and secrets, and saving them into `<workspace>/reports/`.
- **Inputs Consumed:** `workspace_path`, `project_id`, `test_results`, `retry_count`, `is_test_passed`, `bug_diagnosis`, `patched_files`.
- **State Fields Updated:**
  - `current_agent`: `"Report Generator"`
  - `status`: Preserved or set to `"failed"` / `"reviewing"`
  - `logs`: Appended with generated report filenames.

## 4. Conditional Routing Logic

Member 3 provides two deterministic routing functions for LangGraph conditional edges.

### Router 1: `route_after_testing(state: AgentState) -> str`
Evaluates test results immediately following Docker execution.

| Condition | Destination | Rationale |
| :--- | :--- | :--- |
| `is_test_passed == True` | `ROUTE_CODE_REVIEW` (`"code_review"`) | All assertions passed cleanly; advance directly to Member 4 Code Review. |
| `is_test_passed == False` and infrastructure error | `ROUTE_GENERATE_REPORT` (`"generate_report"`) | Docker daemon down or container launch failure; code diagnosis cannot solve host engine failure. |
| `is_test_passed == False` and `retry_count < MAX_RETRY_LIMIT` | `ROUTE_BUG_DETECTION` (`"bug_detection"`) | Test failure with available retry budget; invoke Bug Detection Agent. |
| `retry_count >= MAX_RETRY_LIMIT` | `ROUTE_GENERATE_REPORT` (`"generate_report"`) | Retry budget exhausted; finalize and report failure. |

### Router 2: `route_after_debugging(state: AgentState) -> str`
Evaluates repair outcome after each bug detection iteration.

| Condition | Destination | Rationale |
| :--- | :--- | :--- |
| `is_test_passed == True` | `ROUTE_CODE_REVIEW` (`"code_review"`) | Repair successful; test suite reran and passed cleanly; proceed to Member 4. |
| Inconclusive diagnosis or patch validation failed | `ROUTE_GENERATE_REPORT` (`"generate_report"`) | Root cause cannot be determined or patch is unsafe; halt repair to prevent degradation. |
| `is_test_passed == False` and `retry_count < MAX_RETRY_LIMIT` | `ROUTE_BUG_DETECTION` (`"bug_detection"`) | Rerun still failing but retry budget remains; loop back for another repair attempt. |
| `retry_count >= MAX_RETRY_LIMIT` | `ROUTE_GENERATE_REPORT` (`"generate_report"`) | Max retries reached; finalize and report. |

---

## 5. Member 4 Handoff Contract

When tests pass (either initially or after automated repair), Member 3 routes execution to `ROUTE_CODE_REVIEW` (`"code_review"`).

### State Guarantees at Handoff:
- `is_test_passed = True`
- `status = "reviewing"`
- `test_results = {"passed": True, "total_tests": N, "passed_tests": N, "failed_tests": 0, ...}`
- `patched_files`: Populated if bug fixes were applied (giving Member 4 visibility into repaired source files).
- `workspace_path`: Guaranteed clean on-disk directory ready for static analysis and security scanning.

Member 4's Code Review Agent consumes `workspace_path`, `generated_files`, and `patched_files` to populate `security_report` and assign the final `quality_score`.

## 6. Member 1 Central StateGraph Integration Example

Below is the recommended pattern for Member 1 to wire Member 3 into the central pipeline:

```python
from langgraph.graph import StateGraph, END
from backend.schemas.state import AgentState

# Import Member 3 nodes and routers
from backend.testing_debugging import (
    testing_node,
    bug_detection_node,
    report_generation_node,
    route_after_testing,
    route_after_debugging,
    ROUTE_CODE_REVIEW,
    ROUTE_BUG_DETECTION,
    ROUTE_GENERATE_REPORT,
    NODE_TESTING,
    NODE_BUG_DETECTION,
    NODE_REPORT_GENERATION,
)

# 1. Initialize Central Workflow
workflow = StateGraph(AgentState)

# 2. Register Existing Upstream Nodes (Members 1 & 2)
# workflow.add_node("requirement_analysis", requirement_node)
# workflow.add_node("system_design", design_node)
# workflow.add_node("code_generation", code_gen_node)

# 3. Register Member 3 Nodes
workflow.add_node(NODE_TESTING, testing_node)
workflow.add_node(NODE_BUG_DETECTION, bug_detection_node)
workflow.add_node(NODE_REPORT_GENERATION, report_generation_node)

# 4. Register Downstream Nodes (Members 4)
# workflow.add_node("code_review", code_review_node)

# 5. Connect Code Generation to Member 3
# workflow.add_edge("code_generation", NODE_TESTING)

# 6. Wire Member 3 Conditional Routing
workflow.add_conditional_edges(
    NODE_TESTING,
    route_after_testing,
    {
        ROUTE_CODE_REVIEW: "code_review",              # Hand off to Member 4
        ROUTE_BUG_DETECTION: NODE_BUG_DETECTION,        # Failed tests -> Bug Agent
        ROUTE_GENERATE_REPORT: NODE_REPORT_GENERATION,  # Exhausted/infra failure -> Report
    },
)

workflow.add_conditional_edges(
    NODE_BUG_DETECTION,
    route_after_debugging,
    {
        ROUTE_CODE_REVIEW: "code_review",              # Fixed -> Hand off to Member 4
        ROUTE_BUG_DETECTION: NODE_BUG_DETECTION,        # Retry attempt loop
        ROUTE_GENERATE_REPORT: NODE_REPORT_GENERATION,  # Exhausted/inconclusive -> Report
    },
)

# 7. Wire Report Generation Exit
workflow.add_edge(NODE_REPORT_GENERATION, END)

# 8. Compile Graph
app = workflow.compile()
```

# 8. Environmental Requirements & AI Fallback Behavior

### 8.1 Docker Daemon & Sandbox Image
- Docker Desktop (or Linux Docker Engine) must be running.
- Member 3 runs containers with `network_mode="none"`. To ensure Pytest executes cleanly, ensure the local image `python:3.11-slim` (or `autodev-sandbox:python3.11`) has `pytest` installed:
  ```powershell
  docker build -t python:3.11-slim - <<EOF
  FROM python:3.11-slim
  RUN pip install --no-cache-dir pytest
  WORKDIR /workspace
  EOF
  ```

### 8.2 Live Gemini API vs. Heuristic Fallback
- When `GEMINI_API_KEY` is configured in the environment or `.env`, `TestingAgent` and `BugDetectionAgent` query Google Gemini for dynamic test synthesis and root-cause diagnosis.
- In environments where `GEMINI_API_KEY` is not set or Google API calls fail, Member 3 triggers automatic, deterministic safe fallbacks:
  - `TestingAgent` synthesizes standard syntax-verified Pytest unit tests for discovered source functions.
  - `BugDetectionAgent` applies heuristic pattern-matching to identify stack traces and produce diagnostic summaries.
- Neither condition crashes the LangGraph workflow.
